# Week 5: Recover from errors

Debugging with observations, errors and hypotheses. 90 minutes, three learners.

## Expected outcomes

- Write expected versus actual behavior and reproducible steps.
- Compare three plausible explanations using evidence before changing code.
- Verify a minimal fix and recheck a previously working behavior.

## Before class

Save a working checkpoint or copy. Prepare materials/debugging-cards.md. Use an actual observed problem if available; introduce a known reversible defect only in a disposable teaching copy.

## 90-minute agenda

| Time | Minutes | Activity | What learners do |
| --- | --- | --- | --- |
| 0–10 | 10 | Error stories | Learners share one unexpected result without guessing its cause. |
| 10–25 | 15 | Reproduce the demo | Record expected/actual behavior and the exact sanitized error. |
| 25–40 | 15 | Three hypotheses | Propose explanations and a check that distinguishes them. |
| 40–60 | 20 | Investigate and fix | Learners investigate one issue and request the smallest supported correction. |
| 60–75 | 15 | Verify and regress | Repeat the failing steps, then an old successful path. |
| 75–85 | 10 | Explain the cause | A peer follows the bug report and checks the explanation. |
| 85–90 | 5 | Exit | Name the cause, evidence and remaining uncertainty. |
